# 剪前看看 · 电脑工作台

双击项目里的 **打开剪前看看工作台.command**，也可以运行：

```sh
npm run start:workbench -- --open
```

本机地址为 `http://127.0.0.1:4332/`。使用独立包时按系统双击 macOS 启动器或 Windows 的 `Start Workbench.cmd`。需要 Node.js 22 或以上。Windows 用本机 WASM 人脸关键点模型，macOS 优先用 [Apple Vision 面部关键点](https://developer.apple.com/documentation/vision/vndetectfacelandmarksrequest)，缺少开发工具时使用便携模型。生成试戴图使用本机已安装且通过 ChatGPT 账号登录的 Codex。

## 上传、生成、继续选

1. **新建案例**：选择一张清楚的单人正面照；侧面、背面可选。选发型设计、发型加发色、同款发色或同款卷度；再选风格。展开「多一点控制」可调整发长、刘海、打理方式和备注。
2. **生成案例**：确认照片授权与本次 Codex 处理用途，点击「生成案例」。工作台先检查照片、规划方向，再生成试戴。新案例先制作一张保持原发型的干净基准照，再按所选数量做 1–2 款。同一张原照已有基准时，每轮最多做 3 款。照片不适合时会停在补拍提示。「保存并分析」可只用本机，保存设计建议而不生成图片。
3. **看图和报告**：生成进度按实际完成的图片更新。已保存的能立即打开大图；其余策划方向可以单独点击「生成这款试戴」。每轮的报告可打开浏览，用浏览器打印或保存为 PDF。接回旧案例后，仍可打开原来的高清长图。
4. **再生成一组**：沿用照片，改类型和风格，选择想看的数量。选「同款发色」或「同款卷度」时，优先以当前看到的已成图方案为底；没有成图时从原照的发型出发。
5. **按反馈微调**：选一款点「改这款」，填一处改动后点「生成新版」。旧方案和旧图保留，版本列表可切回；也可以先「保存为新版本」只保留文字方案。
6. **回看与中止**：案例、轮次、版本和本轮报告随时可查。制作阶段可停，已生成的图仍保留。发生失败或应用退出时，不会假装有图、也不会自动重跑已有照片。

脸廓初筛只描述当前照片可见区域，发际线、原生发质、烫染条件和理发可行性由本人及理发师核实。AI 效果在图中标明。

## 本机图像生成

这是用户在当前电脑主动点按钮启动的一次性 [Codex 命令行任务](https://developers.openai.com/codex/noninteractive)。工作台只在环回地址监听；不配置模型 API Key，不启动公开的图像服务。

- Codex 使用自身管理的登录，可用 `codex login status` 查看。Windows 自定义安装路径可在 PowerShell 将 `JQQ_CODEX_EXECUTABLE` 设为 `codex.exe` 的完整路径。工作台不读取账号令牌，也不会在图像工具不可用时切到付费 API。
- 单轮实际调用上限为 3 张（包含需要新生成的基准）。每张是有界限的独立图像任务；过程状态由响应及实际文件决定。
- 后端会验证本轮输入哈希、当前 Codex 执行保存的图片文件以及所属案例和方案。成功后保存到各案例的私有目录。中断时保留完成结果。
- 侧面、背面图片目前作为案例补充档案；自动首轮生成的是正面效果。上传侧照不会自动生成真人背视图。
- 历史数据在 `private-workspace/hair-consultation` 下。用户摄影、预览和工作流记录不进入页面构建包。

「手动交给 Codex」和「导入效果图」也保留。需要排查原有任务时，在项目里使用 `npm run workbench:task -- read <任务号>` 和 `npm run workbench:task -- attach <任务号> <图片路径>`。


源码与迁移说明见 [启动与迁移](../启动与迁移.md)。
